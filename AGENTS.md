# Working rules

Read `README.md` first. It is the sole current design and experiment specification.
Current user instructions override earlier plans. FLOW, SHARING and FIT are
initial candidates, not a fixed final suite. Use README's proposed coverage axes;
source existence is not native-environment validation.
Every core environment must pass README's requirement for both required
disclosure and protected information within the same task.

Keep code, claims and documentation aligned. Distinguish implemented utilities,
proposed backends, admitted data and actual model results. Preserve the historical
evidence in `docs/TAKEAWAYS.md`; it does not define current experiments.

Put design changes in README rather than creating additional planning documents.
Do not restore retired games, prior environment catalogs or duplicate summaries.
Follow the required writing instructions, verify citation claims against primary
sources, and avoid em dashes. Preserve supplied manuscript templates.
Do not run paid models without authorization or restore saved browser state.
Run relevant offline checks, commit scoped changes and push the tracked branch.
